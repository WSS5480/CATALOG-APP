Inbound connectors

Configure these with environment variables (in Render: your service → Environment). Each "Run now" checks for new files and loads them as datasets.

📧 Email (IMAP) … Loads CSV/Excel attachments from unread emails
📂 SFTP pull … Pulls new files from a remote SFTP folder
🔑 API push … Scripts/vendors can POST files with an API token

📧 Email a file straight into a dataset

Pick a dataset and you get an address for it. Anything emailed there — by you, or by a vendor who never touches your account — lands in that dataset and re-runs any flow that reads it. CSV, TSV and Excel, including inside a .zip or .gz.

Hosted apps

      Catalog apps run as their own services and connect here — see catalog-app/README.md
    

    
Apps connect to this ETL Space over the connector API and read the datasets you assign. Each app can point at different datasets, so one ETL Space can power many catalogs.

  


  

    

      
Catalogs

      
      
      
      
      
    

    
Each catalog is a complete configuration — its own datasets, its own column matching, its own wording. One deployed app serves all of them: open it with ?catalog=<name> on the end of the URL, or pick from the dropdown inside the app. You never need a second Render service to add a catalog.
